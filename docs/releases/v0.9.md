# JARVIS v0.9 — integrated local development runtime

Phase 9 integrates Phase 2–8 policy/execution, durable authority/tasks/journal,
scoped memory, cognition/conversation, world model, initiative and notifications.
The implementation adds one shared composition root, a bounded always-on
foreground runtime, authenticated loopback HTTP v1, read-only doctor, current
owner metrics, explicit development credential provisioning and comprehensive
user/operator/developer references. It does not add a second privilege path.

Requirements addressed: ARCH-001–004, IAM-001/003/004/007, PER-001–003,
CAP-001–003, TASK-001/002, EVT-001, MEM-001–004/006, WORLD-001–003,
AUTO-001–003, COM-001, COG-001, SEC-001–004, REL-001/002, DEV-001/003.
COG-002/WORLD-004 remain PROPOSED; REL-003 telemetry is not a binding SLO.
ADR-T10 documents provisional runtime/auth/API integration; existing ACCEPTED/
OPEN decisions are preserved.

## Use and migration

Follow [quickstart](../getting-started/quickstart.md) and
[local models](../getting-started/local-models.md). Explicit new-store provisioning:

```sh
uv sync --locked --python 3.12
uv run jarvis runtime-init --data-dir .jarvis/dev --model-provider fake
uv run jarvis doctor --config .jarvis/dev/runtime.json
uv run jarvis serve --config .jarvis/dev/runtime.json
```

Client and worker tokens are separate kinds, private files, hash-only persistent
bindings, current session expiry/revocation. Existing stores need online backup
and explicit schema migration 8; `serve` neither migrates nor bootstraps/regrants.
See [backup/restore](../operations/backup-restore.md). Credentials expire after
24 hours by default; trusted host issuance/rotation is explicit.

## Limits and owner decisions

Implemented: one process/host, serial finite scheduling, current scoped worker
authority, bounded HTTP/thread admission, actual attempt recovery, owned history/
tasks/inbox, numeric diagnostics, offline fake model and loopback local adapter.
Provisional: SQLite/schema/claims, local development auth, FastAPI v1 contracts,
single-worker scheduling, optional Linux service template. Planned: production
auth/provisioning, tamper-resistant audit, distributed claims, physical retention,
operator ambiguity reconciliation, real adapters/public deployment.

No installed genuine model weights/server were available for this acceptance;
actual loopback protocol-server tests pass but genuine inference remains
unverified. Cloud stays off without fallback. No real physical device, external
message, GUI/voice/camera, autonomous research, biometric identity, social
profiling or multi-agent framework is introduced. Local OS/file owners are trusted;
they can read secrets/database, and old backups can roll back revocation. Host
security/credential rotation after restore remain operator responsibilities.

No remaining owner decision blocks this authorized development milestone.
Production IAM-005/PER-004, final API/storage/scheduler, consent/collection/
retention, calibrated risks, channel destinations/urgency, ambiguity reconciliation
and SLO targets remain OPEN. Recommended Phase 10: authenticate/provision a real
deployment and validate a genuine local model before exposing or adding privileged
real integrations. A narrowly enrolled real sensor can follow explicit collection/
retention decisions; historical social/wearable roadmap proposals remain proposals.
